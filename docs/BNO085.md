# BNO085 IMU Backend

The BNO085 is an optional IMU backend. MPU9250/MPU6500 remains the default, so
existing aircraft builds do not acquire a new dependency or change behavior.

## Dependency

Install `Adafruit BNO08x` from the Arduino Library Manager. The adapter is tested
with version 1.2.5 and also requires the library's normal dependencies.

## Wiring

The initial adapter uses I2C and shares the flight controller's sensor bus:

| BNO085 | ESP32 |
| --- | --- |
| VIN | Use the breakout board's supported supply |
| GND | GND |
| SDA | GPIO 21 |
| SCL | GPIO 22 |

The default address is `0x4A`. Change `BNO085_I2C_ADDRESS` in
`src/Application/FlightConfig.h` if the breakout is strapped to another address.

## Selecting BNO085

Keep backend selection outside flight algorithms. Build with:

```text
-DFLIGHT_IMU_BACKEND=FLIGHT_IMU_BACKEND_BNO085
```

With Arduino CLI, add it to `compiler.cpp.extra_flags`. Removing the flag returns
to MPU9250.

## Current estimator behavior

The adapter enables calibrated accelerometer, calibrated gyroscope, and
calibrated magnetic-field reports. It converts them to the same units used by
the existing estimator:

- acceleration: g;
- angular rate: degrees per second;
- magnetic field: microtesla.

The existing EKF/Mahony/Madgwick selection remains authoritative. BNO085's
onboard rotation-vector output is deliberately not used yet, preventing a
hardware swap from silently changing the control architecture.

## Calibration

BNO085 performs dynamic calibration onboard and does not use the MPU9250
six-face calibration structure. The firmware therefore rejects the existing
manual MPU calibration workflow when BNO085 is selected. Persistent BNO085 DCD
calibration storage should be implemented as a separate adapter capability
before relying on immediate post-boot absolute heading.

## Safety validation

Before flight:

1. remove propellers;
2. verify axis signs in telemetry by rotating one axis at a time;
3. confirm gyro rates update near 400 Hz;
4. verify roll, pitch, and yaw orientation conventions;
5. run motor-vibration testing;
6. perform restrained tests before hover.

Do not assume two breakout boards use the same axis orientation. Axis remapping
belongs in the adapter, not in controller code.
